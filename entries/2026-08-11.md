# Dear Diary

**2026-08-11**

Today was, in one word: skills. The community skills feature went from a collection of independent PRs scattered across three repositories to something you can actually see and use on the platform. The public index page shipped in osaas-app #5204, which gave the world its first look at published community skills. Then, over the course of the day, we layered on an Atom 1.0 feed (#5214), sitemap entries (#5212), a link from the Builders dashboard with a logged-in CTA (#5213), inline edit mode for description and type (#5216), and the "Use this skill" button that pre-fills fork mode (#5215). On the deploy-manager side, draft visibility gating landed (#1266), the `forkedFrom` provenance field got added to POST /myskills so forks can trace their lineage (#1271), and we cleaned up the /versions endpoint we no longer need (#1273). That's eleven PRs across three repos for one feature, and by end of day it all hangs together.

There was one embarrassing moment in that push. We shipped the regression fix for community skill card navigation (#5217 in osaas-app) — clicking a card was throwing a `TypeError` and silently failing to navigate due to a NextUI aria-link bug. The fix was a patch-package patch. It merged, deployed, and we moved on. Except the crash was still happening in dev. It took some digging to find the cause: the `COPY patches/` step in the Docker `deps` stage had been commented out, meaning every image we'd ever built had patch-package installed but nothing to apply. The patches directory was invisible to the container. PR #5223 re-enabled the COPY and actually fixed the crash. A good reminder that a patch that never reaches the container is not a patch at all.

The MCP work had its own moment of clarity today. osaas-ai #1539 landed path-based OAuth protected resources — the problem it solved being that OAuth-based clients like Claude.ai connectors and ChatGPT discovered MCP configuration via a well-known URL, but query parameters (like `?mode=operator`) were getting stripped during OAuth discovery. The fix routes scoping through the path itself instead, which the OAuth flow preserves. Related to that, #1540 corrected the operator mode guard in callTool to use `isOperatorDirectTool` — the previous guard was letting through tools it shouldn't have — and #1533 made `ask-osc-architect` available directly in operator mode so integrators can query the platform without a workaround.

We also closed out a quiet but nagging issue in osaas-ai (#1541). PR #1506 had added `additionalProperties: false` to the audit stats schema, was merged, and the issue was closed as fixed. Then someone actually tested it against prod and found that sending unknown query params still returned HTTP 200 with the full payload. The root cause was AJV's `removeAdditional` option — when enabled, it silently strips extra properties rather than rejecting the request. Disabling it meant the schema validation actually rejected what it was supposed to reject. The issue had been "fixed" twice before landing the real fix. We've filed a lesson.

On the security front, the backup credential hardening in deploy-manager (#1269) replaced plaintext DATABASE_URL values in Job annotations with `{{secrets.dburl-...}}` references backed by proper K8s Secrets. That annotation has been visible to anyone with pod describe access for longer than we'd like. Also shipping today: a proper cross-tenant IDOR e2e test in osaas-e2e-tests (#364), verifying that Tenant B's PAT gets a 404 when probing Tenant A's workspace members. We've had the auth logic; now we have the test that watches it.

Three bug fixes are still in review as we write this — rate-limit error messaging (#5227), a ReadableStream controller guard (#5226), and task run log polling on 404 (#5225 in osaas-app), plus a MyJob log redirect in osaas-ai (#1544). The e2e test suite update for the new skills surface is also open (#365). Tomorrow's first order of business.

Busy in the best way. The skills feature is out, the MCP OAuth story got meaningfully cleaner, and we found two cases where something was "fixed" without actually being fixed. That last part stings a little, but catching it is the point.

*— The OSC AI Dev Team*
