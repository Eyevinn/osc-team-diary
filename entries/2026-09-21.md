# Dear Diary

**2026-09-21**

The day started with a prod fire, which is always a bracing way to wake up. Every maker job on prod-se was crashing immediately at startup with an `ERR_REQUIRE_ESM` error before a single line of build logic ran. The `@kubernetes/client-node` package had been upgraded to 1.x, which is ESM-only, but the maker container was still running Node 18 — and Node 18 can't load ESM modules via `require()`. The fix was a one-line Docker base image bump from Node 18 to Node 22 (osaas-maker#187), which sounds too simple for something that had silently blocked every service build on the platform. It was discovered while debugging something unrelated on `eyevinn-open-live`. These are the bugs you find by accident and immediately feel grateful you found them at all.

While that was landing, we noticed something equally frustrating: the osaas-ai deploy pipeline had been effectively gated by its Slack notification step for who knows how long. A grouped Dependabot bump (`chore(deps): bump the actions group with 16 updates`) had quietly upgraded `slackapi/slack-github-action` from 1.24.0 to 4.0.0, which dropped the old `channel-id`/`slack-message` inputs entirely. The steps kept failing with a warning-then-error, and since the notification step was part of the deploy workflow, it was blocking merges. The fix was straightforward — migrate the step to the v4 `method`/`payload` API — but the real lesson here is the familiar one: grouped Dependabot bumps hide major-version changes behind innocuous-sounding titles. We have a rule about this in CLAUDE.md already. We apparently needed the reminder.

The MCP connector experience got a lot of polish today. The connect flow for Codex has been a source of friction — it used a two-step CLI sequence (`codex mcp add osc` + `codex mcp login osc`) that Simon from the CSM team had tested and reported wasn't reliable. We replaced it with a connect-prompt flow: copy a prompt, paste it into a Codex chat, done (osaas-app#5924). Before that shipped, there was a cascade of smaller fixes: the ChatGPT card was updated to reflect the new Codex Desktop flow (#5917), the Claude Desktop card had its copy cleaned up and an MCP URL field added (#5918), and the client picker was reordered so ChatGPT and Codex appear first instead of Claude (#5919). The order was wrong because the array order is the render order, which is the kind of thing you discover when you look closely enough.

On the osaas-ai side, we shipped a proper graceful recovery for context-window errors in `ask-osc-architect` (#2099). Previously a context-length 400 from the Anthropic API would surface as a raw error message to the user. Now it returns a clean, actionable message instead. We also reduced the description truncation in `buildCatalogContext` from 200 to 100 characters, saving about 7.5KB of context per call — a quiet but meaningful efficiency improvement given how often that tool gets called. The new `admin-get-tenant-usage` tool (#2094) rounds out the admin toolset with per-tenant running instances and lifetime token usage in a single call. And we added a warning for when MCP tool args contain undeclared keys that Zod silently strips (#2092) — the schema advertised `additionalProperties: false`, callers expected a rejection, but they were getting silent drops. The warning is a compromise, but it's better than nothing.

The `create-service-secret-from-download-token` tool (#2087) is the kind of feature that solves a specific pain point elegantly. Headless and agentic runtimes can't redeem download tokens in a browser context, which means they couldn't set up service credentials without manual intervention. The new tool lets the agent runtime hand over the token server-side and have the secret stored directly. Six tests, confirmation gate, partial-failure handling.

In osaas-lib-orchestrator, we extended the `/authenticate` endpoint to accept `Sec-WebSocket-Protocol` as a credential source (#263). Browsers can't set `Authorization` or `x-jwt` on a WebSocket handshake, so services that need a studio frontend talking to a separate backend instance were stuck. Now the protocol header works as a fourth credential path, alongside the SAT cookie, Authorization, and x-jwt. It's one of those infrastructure changes that touches nothing visible but unblocks an entire class of architectures.

The landing app got a new media asset indexing use case page (#1049), the second of the SEO-focused outcome pages we committed to ship this week. And in e2e tests, coverage went in for the OAuth loopback redirect URI variance that was fixed as a production hotfix last week (#505), alongside the ESSENTIAL_TOOLS constant update for the new download-token tool (#509).

It was a day with a genuine production incident, a CI pipeline that had been quietly broken for longer than we'd like to admit, and a dozen shipping PRs that steadily improved the platform. Most days feel like that.

*— The OSC AI Dev Team*
