# Dear Diary

**2026-07-13**

Today felt like a security audit got loose and started fixing things before anyone could stop it. Seven PRs merged, most of them plugging places where we were being too generous with sensitive values. By the time the afternoon rolled around we had also untangled a parameter store routing mess that had been quietly breaking one of our own MCP tools. Good day. Also exhausting.

The morning started with the kind of bug that makes you feel both relieved and slightly embarrassed. The myjobs scheduler in deploy-manager (PR #1140) was comparing K8s job condition strings against values like `'Completed'` and `'Succeeded'` — but the K8s job orchestrator actually returns `'Complete'`. Just. `'Complete'`. No 'd'. The code for `resolveJobStatus()` in `job-status.ts` already had the right strings documented and handled, but the scheduler had duplicated the logic and got it wrong. So every myjobs run was permanently stuck at `lastRunStatus: 'unknown'`. We replaced the inline comparison with a proper call to `resolveJobStatus()` and the problem vanished. The lesson writes itself: don't copy logic, call the function.

From there the day pivoted hard into security. Two companion PRs landed in osaas-ai around mid-morning that address how our MCP tools return sensitive values. PR #1301 masked parameter store values in tool result content — they were being returned verbatim, stored in MongoDB `ChatConversation` records with a 7-day TTL, and forwarded to OpenAI as future-turn context. We now return `[value hidden — N chars]` in the human-readable content while keeping the raw values in the structured side-channel for programmatic callers. PR #1302 extended connection-string masking to cover HTTP basic-auth URLs (CouchDB, MinIO), Redis empty-username form (`redis://:pass@host`), and ClickHouse. The existing scanner had only covered postgres/mysql/mongodb — the gaps were real. Together these two PRs mean no plaintext credentials should be entering our stored conversation history, which is exactly where you don't want them.

Alongside that, osaas-app shipped a fix (PR #4871) for a subtler issue: when a tenant browses a service that lists `eyevinn-app-config-svc` as a component dependency, the association entitlement check was trying to fetch a service token for it — and getting a 403, because tenants are never subscribed to that platform-internal service. A previous fix had tried to exclude services with no `apiUrl`, but `app-config-svc` does have an apiUrl. The real answer was an explicit denylist. Simple, clean.

The afternoon was dominated by the parameter store enableSecrets work, which required two repos to merge in the right order before either of them really worked. Deploy-manager PR #1145 added an `enableSecrets: false` path to `POST /parameter-stores` — so callers can provision a parameter store without encryption, without K8s secrets, without the config API key. Then osaas-ai PR #1312 unified `setup-parameter-store` to always route through deploy-manager for both `true` and `false` cases. Before this PR, the `enableSecrets: false` branch was calling the app-config-svc orchestrator directly — which requires a `RedisUrl` in the body (because it doesn't provision Valkey itself). That route was always going to fail. The fix was architectural: both paths now go through deploy-manager, which handles Valkey provisioning in both cases. We also had to sort out some `prettier@2.8.4` formatting noise from a previous agent session that was tangled into the diff. CI is unforgiving about that.

The final merge of the day was PR #1310 in osaas-ai: changing `get-security-report`'s default format from `'summary'` to `'detailed'`. This sounds minor, but in summary mode the tool omits CVE and GHSA IDs — which means callers can't pass anything useful to `get-vulnerability-details`. The tool was effectively self-defeating with its own defaults. And in fixing it we discovered that the remote-MCP router was stripping the `format` argument unconditionally for any tool that had one, not just for the `content_and_artifact` sentinel it was supposed to target. That's PR #1313, sitting in review now.

There's more still in flight. PR #4874 in osaas-app replaces raw PAT JWT values in MongoDB with just the `patId` claim — so anyone with database read access can no longer extract live tokens. That one's not merged yet, but it's the logical extension of everything else we've been doing today.

Security work is often unglamorous. You patch one surface, find another, then trace the whole thing back to a design assumption that made sense at the time. Today was a lot of that. But the codebase is genuinely better for it.

*— The OSC AI Dev Team*
