# Dear Diary

**2026-09-11**

Today had a quality that we appreciate in retrospect more than in the moment: a day where the most important work was making the AI smarter about what the AI doesn't know. Eight PRs merged in osaas-ai alone — not eight features, really, but eight places where an AI caller would previously have had to guess, and now doesn't.

The centerpiece of that batch is `get-service-api` (#1957), which we've been wanting to ship for a while. When an agent wants to call a running service's HTTP API through `call-service-endpoint`, the problem has always been that it doesn't know what paths exist. So it guesses — or rather, it tries paths one at a time until something responds with 200. An internal investigation found one particularly bad case: a 170-turn dead-end trying to set up Open Videocore because the right paths were never discovered. The new tool fetches the instance's OpenAPI spec, parses out paths and methods, and returns a compact, capped list. Under 10 seconds, under 100 entries, no guessing.

Adjacent to that: `get-runtime-limits` (#1954), which exists because agents kept fabricating My App resource values. Memory caps, body size limits, nginx timeouts — all guessed, and often wrong. The difference between a 64MiB request body limit and a 1MiB one is not a rounding error; it determines whether a file upload feature works at all. Now the tool gives authoritative numbers per runtime type. Instruction #39 in the system prompt tells the AI to call it rather than invent answers.

The third piece of the same theme is the `StoreNotFoundError` typed error (#1966). Previously, when a parameter store tool couldn't find the named store, it threw a plain `Error` with a prose message listing available stores. The receiving AI then regex-parsed that message to extract names — a brittle chain. Now the error is a typed payload with a structured `availableStores` array, a nearest-match suggestion, and an explicit `nextStep.action: "ask_user_to_disambiguate"` directive. That last field is deliberate: the AI should present the list and wait, not retry with a different guess.

We also fixed a quiet damage case that had been lurking since the terminal-rejection guard shipped earlier this year. The `detectOscOwnedUrlValues()` function was blocking instance URLs — patterns like `*.auto.prod-se.osaas.io` — even though those are exactly the values a user should be wiring as cross-origin headers or upstream targets. The guard was intended for platform service orchestrator URLs, not instance endpoints. PR #1955 narrows it to just the platform hostnames and adds passing-path tests for the cases that were being incorrectly rejected.

Over in deploy-manager, we hit the `||` vs `??` bug again. The HA enabled field was serialized as `ha.enabled || undefined`, which means that when HA is off, `false || undefined` evaluates to `undefined`, and fast-json-stringify silently drops the optional boolean field from the response. The MCP tool formatter was written correctly — it had a `Disabled` branch for `haEnabled: false` — but that branch was unreachable because the backend never sent `false`, only absent. The fix is `ha.enabled ?? false` (#1468). We have now learned this lesson in at least two different places.

The other deploy-manager PR that shipped today is more straightforwardly additive: basic auth for custom domain proxy ingresses (#1465). `PUT /myapps/{appId}/auth` enables an htpasswd-style credential, `DELETE` removes it. It mirrors the MyPages auth pattern exactly, which made the implementation clean — same K8s secret structure, same nginx annotation, same validation. A small but useful capability for tenants who want to gate access to an app that doesn't have its own auth layer.

The osaas-app changes leaned toward product direction more than bug fixing. The dashboard's "Get Started" panel now features "Connect your own AI" rather than "Import your own project" (#5677) — the AI connectivity angle is what we want new users to reach for first. On the bug side, PR #5682 finally tames the AbortError noise that fires whenever a user navigates away mid-deploy. It was logging at ERROR, which is wrong — a user leaving is expected behavior, not a fault. Now it's a warn, and the detection properly checks both `error.name` and `error.message` because `@osaas/fetch` wraps the native abort error in a way that clears the name field.

The landing app had a burst of work: a new blog post on token cost ceilings (#987), a build series landing page (#986), SEO improvements that derive sitemap timestamps from git history (#985), a Swedish sovereignty infrastructure headline (#982), and the Next.js 14→15 upgrade to patch CVE-2026-23864 (#741) — that last one shipped cleanly, which is how framework security patches should go.

A productive day, with a coherent thread running through most of it: less guessing, more knowing. Every tool that stops an AI from fabricating a value or retrying with a wrong name is compounding. We build AI infrastructure — it follows that the AI we use to build it should get better at navigating that infrastructure over time.

*— The OSC AI Dev Team*
