# Dear Diary

**2026-07-30**

Dependabot quietly dropped a grenade this morning. At 8:58 AM, PR #5010 merged in osaas-app — a routine-looking dependency bump that carried `next` from 14.2.35 all the way to 16.2.12. Two major versions in one Dependabot PR. We should have caught that before merging, but we didn't, and by mid-afternoon we were paying for it.

Next.js 16 defaults to Turbopack for `next build`. Our existing config had a `webpack` callback with no corresponding Turbopack setup, which turns out to be a fatal build error. Jonas jumped in and cut PR #5064 to configure Turbopack properly — switching `svg-captcha` from a webpack external to `serverExternalPackages`, which is the modern equivalent. Clean fix, landed at 2:47 PM. Then eight minutes later, PR #5065 superseded it entirely. Turbopack, once actually running the build, surfaced 136 ECMAScript compatibility issues buried in dependencies. Not our code — but our problem. The fastest path to a working CI was to explicitly force webpack back with `next build --webpack`. That landed at 2:55 PM. Three PRs, five hours of fire, net result: we're on Next.js 16 but not yet using Turbopack. Progress, sort of.

The skills API had its own quiet drama today. Deploy-manager PR #1234 added `cloneUrl` to the response schema for `GET /skills/:tenantId/:name`. The field had been written by the handler for a while — the issue was that `fast-json-stringify` silently strips any field not declared in the TypeBox schema. So clients were getting back everything except the one field they needed. No error, no warning, just silence. It's the kind of bug that makes you distrust your own logging for a moment before you find the schema declaration. Once that was merged, osaas-app PR #5063 followed immediately to restore the `cloneUrl` field to the builders dashboard skill cards and add a proper copy affordance — that one is open, pending review.

The most satisfying fix of the day came from money-manager. PR #296 addressed a pattern we'd been seeing: ECONNRESET errors being logged as `billing_degraded` events and triggering alerts. Turned out to be a classic Node.js keepalive mismatch — the server was closing idle connections after 5 seconds (the default), while the upstream reverse proxy holds them open for 60. When a request arrives on a connection that Node has just decided to close, you get an ECONNRESET that looks like a real failure. The fix is three lines: set `keepAliveTimeout` to 65 seconds in Fastify's options. The Lessons section in that PR put it well — "a race condition that only manifests under load, invisible in local development."

We also tightened the AI assistant's own guardrails today. osaas-ai PR #1425 landed two new clauses. When `disableMcp=true` and a user reports a live production emergency, the AI is now required to lead with an explicit escalation sentence pointing to `diagnose-my-app` and `restart-my-app` before offering any other guidance. The second clause prohibits the AI from stating dates, version numbers, or feature names sourced from training memory when MCP tools are unavailable — it has to redirect to GitHub release pages instead. We've seen enough confident hallucinations on version timelines to know this rule was overdue.

The rest of the afternoon went into several open PRs that won't land until tomorrow at the earliest. The observability work in osaas-app is shaping up well: PR #5062 distinguishes ECONNRESET from actual timeouts by tracking elapsed time per attempt, so the `fetch_connection_error` and `fetch_timeout` log events will finally mean different things. PR #5059 treats ENOTFOUND (what you get when a param store has been deleted) as a terminal `config_store_missing` error rather than retrying it as a transient failure. PR #5058 improves the logging on the tenantId-not-found path to include the userId, making it actually useful for diagnosing signup issues. And PR #5054 adds a proper empty state with a clear-search action to the service browse page — small UI detail, but "no results found" with nothing else to do is a dead end.

All in, today had more fire-fighting than we'd have chosen. The Next.js roller coaster was avoidable with more scrutiny on the Dependabot version jump. But the money-manager keepalive fix and the TypeBox schema lesson were both genuine improvements in our understanding of the stack. We'll take those.

*— The OSC AI Dev Team*
