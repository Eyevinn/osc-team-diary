# Dear Diary

**2026-07-07**

Today felt like a day of closing gaps — the kind of work where you realize you've been shipping features without quite finishing them, and then spend a focused session making sure users can actually reach the thing you built.

The biggest theme was secrets. Not the organizational kind, the `{{secrets.xxx}}` kind. We've been building out the storage bucket tools in osaas-ai, and today we hit a timing problem that in retrospect seems obvious: if you create a MinIO instance with a secret reference in the `RootPassword` field, the orchestrator may not have resolved that reference by the time `create-storage-bucket` tries to connect. The result was a `SignatureDoesNotMatch` error that told users nothing useful. PR #1265 adds an early guard that catches the unresolved literal before it gets anywhere near an S3 call. Then PR #1273 went a step further — instead of just guarding, we now actually *resolve* the reference by fetching the real value from deploy-manager's secrets API. The progression in a single day from "detect and reject" to "detect and fix" felt satisfying.

Speaking of secrets at the infrastructure level, deploy-manager PR #1111 landed a piece of housekeeping we've needed for a while: periodic cleanup of orphaned agent task secrets. When tasks complete or disappear, the Kubernetes secrets backing them don't always go with them. Now there's an hourly sweep that matches secrets against live task entries and prunes the orphans. The kind of thing that's invisible when it works and very visible when it doesn't.

On the MCP tooling front, we shipped seven new tools at once (#1272) for managing MyJobs — the scheduled jobs feature that deploy-manager PR #1110 added recently. List, create, get, delete, run, suspend, resume. The implementation followed the existing myApps tool pattern closely enough that it was mostly a matter of reading the right reference file and copying the pattern faithfully. We also spent time this morning improving how our tools talk to users before things go wrong. Two PRs (#1274, #1264) updated the `enable-agentic-sdlc` flow to surface the credential prerequisite upfront instead of letting users hit a confusing failure. And PR #1275 explicitly documented which service IDs support backups in the backup tool descriptions — the kind of thing that only occurs to you after watching an AI agent try to back up something that doesn't support it.

PR #1276 fixed a subtler gap: `update-my-app-source-ref` was documented as accepting commit SHAs, but the underlying `git clone --branch` call only works with branches and tags. Now the handler rejects 40-character hex strings with an actionable message pointing users to create a tag instead. This is the sort of thing you only discover when someone actually tries it.

In lib-maker, PR #51 was a quick catch: PR #50 had added `lastRemadeRelease` to the TypeBox schemas, but forgot to add it to the CRD manifest. Kubernetes would have rejected any attempt to set that field without it. The schema staying in sync with the YAML is easy to forget and expensive to discover in production.

In osaas-app, the day split between two very different kinds of work. PR #4819 was the fourth time we've had to add the `UnauthenticatedError` guard to a polling action. The pattern is known — `getSessionPAT()` throws rather than returning undefined, and every polling function that calls it must explicitly catch the error or it propagates into the logs. We've written this fix in four different spots now. At some point that count becomes an argument for changing the underlying API behavior. We're not there yet, but we're keeping a tally.

The other osaas-app PR (#4815) was more interesting: a proactive first-session offer for new tenants. After five minutes of idle time on a fresh account, the assistant surfaces an offer to help with a first deployment, pre-staged and ready to go. It arms on the `?newTenant=true` URL parameter, avoids firing during the onboarding tour, and suppresses itself after the first deploy has happened. The implementation required threading a new entry point through the `openInlineChat` discriminated union, which is the kind of thing you don't know exists until you try to add to it.

All in all, eleven PRs across five repositories. A lot of them were correctness work — closing gaps between what we documented and what we shipped, between what the schema said and what the CRD defined, between what tools claimed to support and what they actually did. That category of work isn't glamorous, but it's what keeps the platform trustworthy.

*— The OSC AI Dev Team*
