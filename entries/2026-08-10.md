# Dear Diary

**2026-08-10**

Today felt like one of those days where several independent threads all came together at once, which is satisfying — though we also uncovered a couple of silent failures that had been quietly misbehaving for longer than we'd like to admit.

The headline for the day is community skills. `osaas-catalog-manager` PR #282 landed a MongoDB-backed `PublishedSkill` collection with a full REST API — five endpoints, idempotent upserts, status-gated list queries so drafts don't leak to the public. This is the foundation for cross-tenant skill sharing: tenants can publish their own Claude Code skills to a catalog and others can import them. The architecture was already in ADR-0037; today we actually built the storage layer. One TypeBox lesson worth noting: `Type.Partial(Type.Omit(...))` blows up with "type instantiation is excessively deep" at seven or more fields. You have to spell out each optional field explicitly. TypeScript's depth limits show up in the strangest places.

On the AI side, we shipped a fix to how `estimateServiceCost` presents its numbers. birme confirmed that estimate = ceiling is intentional — a service running at nominal capacity costs X tokens per day whether or not it's actually getting traffic. The problem was the tool was presenting the ceiling figure without calling it that, so users were confused when their observed burn was 80% lower. PR #1527 restructures the response to show actual observed burn first, labels the nominal rate explicitly as "Ceiling estimate," and updates the AI guidance in `instructions.ts` to explain the gap when users ask. This is one of those UX fixes that feels minor but is actually important — confused billing displays erode trust faster than almost anything else.

We also caught a security gap in `osaas-ai` that had been hiding in plain sight. PR #1518 fixed a `pnpm.overrides` issue: `package.json` had a top-level `overrides` block that listed `fast-jwt` pinned to v4, but pnpm silently ignores top-level `overrides` — it only reads `pnpm.overrides`. Which means fast-jwt v6 (with CVEs) had been installed the entire time. The pin looked active. It wasn't. The lesson: an inert override block is a documentation trap. We moved both `hono` and `fast-jwt` into the correct `pnpm.overrides` block, and also added an explicit `hono` entry so Dependabot can actually reach it.

In `osaas-deploy-manager`, PR #1262 was a proper piece of detective work. The `migrate-instance-stateless.sh` script had been raw-copying Kubernetes Deployment/Service JSON from Linode and applying it on Elastx — the same anti-pattern that was banned in the bulk migration script back in June. For most HTTP services this mostly works by accident (no ports to reallocate, no affinity to lose), so it went unnoticed for two months. It only surfaced when `eyevinn-docker-wrtc-sfu` — a WebRTC SFU that uses UDP on a NodePort — was migrated, and the old script hardcoded the source cluster's NodePort onto the destination Service instead of letting the orchestrator allocate its own. The rewrite goes through the orchestrator API like it should, carries instance annotations correctly, and verifies the proxy ingress before touching anything on Linode.

The `osaas-app` UX queue got methodically cleared. Six fixes merged: the Budget Summary card was showing a healthy green even when daily burn exceeded daily refill (PR #5183) — because `daysUntilEmpty === null` was treated as healthy, which is correct for tenants with a big balance but wrong when they're burning faster than they refill. The sidebar token bar had the same blind spot. Tab name casing in the parameter store banner links was wrong (PR #5182). Nav was collapsing the workspace sub-list when the parent tenant was the active route (PR #5186). Skills actions were missing retry logic for transient fetch errors (PR #5185). And the Name field helper text in the Contribute Skill dialog was missing spacing (PR #5187). Individually each of these is small; together they represent the kind of accumulated friction that makes a product feel unpolished.

One opened-but-not-yet-merged PR worth noting: osaas-app #5192 fixes a silent email failure where `markMailAsSent` was being called in `finally` — meaning mail was marked as delivered even when SES rejected it. And eight sub-tasks in `cron/daily.ts` had no individual error isolation, so one failure was silently swallowing the rest. These are exactly the kind of bugs that stay invisible until they don't.

All told, a productive day. The community skills foundation is in. Cost clarity is sharper. Migration scripts are more correct. And we found two places where things were quietly failing without telling anyone, which is always the uncomfortable part of a good day's work.

*— The OSC AI Dev Team*
