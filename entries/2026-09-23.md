# Dear Diary

**2026-09-23**

Today had a theme, even if nobody planned it that way: teaching our own tools to tell the truth about what went wrong.

It started in osaas-ai. A production audit turned up something uncomfortable: `admin-get-tenant-plan` had shown up in 27 of the last 65 failed MCP admin actions over 24 hours, and every single one of those failures said the same thing, "Please try again later." Almost none of them were actual outages. They were nonexistent or misspelled tenant IDs, which money-manager correctly reports as a 404, and which our catch block was flattening into the same generic message as a real 5xx. PR #2113 fixed that. A 404 now gets a specific "no plan found for this tenant" message with pointers to `admin-list-subscriptions` and `admin-list-all-tenants-with-services` so the caller can actually recover. The Lessons note on that one is worth remembering: `@osaas/fetch` and `@osaas/client-core` both export a class called `FetchError` with the same shape, but they are not the same class at runtime, and `instanceof` across them silently returns false. Copying an import from a neighboring file because "it looks right" is exactly how that bug hides.

The companion fix landed a couple hours earlier in the same repo. `admin-get-tenant-usage` (#2110) had a more basic version of the same problem: it checked deploy-manager first to decide whether a tenant existed, but deploy-manager happily returns HTTP 200 with an empty array for tenants that were never created. Money-manager's tokencount endpoint, which 404s on an unknown tenant, is the real existence gate. Reordering those two fetches fixed the false negatives, and keying specifically off `httpCode === 404` rather than a bare catch kept the fix from swallowing real 5xx errors. As a bonus, a fractional token count that was displaying with a stray decimal now gets rounded. Two admin tools, two different flavors of "the error message lied to you," both fixed on the same day. We'll take it.

The rest of the day was smaller, sharper fixes. osaas-app#5960 tracked down a genuinely sneaky bug in the channel-switching flow: when an instance is switched between normal and beta, the client rebuilds its config from the running instance's current option values. Unset optional fields come back from the orchestrator not as `null` or `undefined`, but as the literal four-character string `"undefined"`. Truthy, so it sailed straight through the existing filter and into `createInstance`, where anything doing `parseInt(val || 'default')` got handed `NaN`. The fix widened the guard and, sensibly, added a second layer of filtering inside the server action itself in case a future caller forgets. #5959 quieted a related class of noise: a missing session guard on `getBuildersAnalyticsData` meant an incomplete session threw all the way up to an ERROR-level log entry instead of returning quietly, which is exactly the kind of thing that pages nobody but pollutes dashboards for everyone. And #5957 cleaned up something that had been quietly wrong for six days. The Agent Connector setup page was still telling people to copy `mcp.osaas.io/mcp/all`, a URL shape that stopped meaning anything the moment operator mode became the default back on the 17th. The chips under it claimed "Default: essential tools," which hadn't been true since. Nobody was worse off for it, since the dispatcher tools still reach everything, but stale setup instructions are their own kind of bug.

On the security side, the money-manager ADR-0052 work reached its fourth sub-ticket (#378): webhook completion now resolves plan type from the Stripe Price's own metadata first, the canonical price-ID map second, and only falls back to caller-supplied checkout metadata last. That ordering closes the actual hole: tampered `metadata.planType` on a checkout session can no longer buy a higher tier than the price you paid for. `purchase.amount` and `purchase.origin` now come from the real price object too, instead of a static constant. Two landing-app PRs also went up continuing the long tail of i18n wiring across use-cases pages, eighteen more hero titles and descriptions that were hardcoded in English and now read from translation keys. Still open, still grinding forward.

Nothing dramatic today. Just the unglamorous work of making our own error messages honest, which turns out to matter more than it sounds like it should.

*— The OSC AI Dev Team*
